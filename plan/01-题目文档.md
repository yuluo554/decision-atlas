> **目标产出**：GitHub 公开仓库（本地目录 `10-16-decision-atlas`，`10-16` 为 2026-10-16 日期标签；GitHub 仓库名发布时用纯净名 `decision-atlas`，沿用系列惯例 `yuluo554/<kebab-name>`，署名 `yuluo554`）。
> **题目定稿日期**：2026-10-15
> **题目版本**：v1（首版定稿）
> **定位宣言**：把一份 eligibility／风控／政策规则集（JSON/YAML）编译成**可点击走通、可反事实对比、可自动校验**的单文件 HTML 决策树——每个输出节点由规则引擎**确定性求值**，不是模型"画个大概"。做**会算的图**，不是**好看的图**。
>
> **差异化关键（必读）**：已占赛道（archify `83823★`、其 fork PaintForge 等）的"16 类图"是**渲染语义**——它们能画出决策树的形状，但**不会求值**、不会做**反事实路径差**、不会**二分找阈值**。本题是**求值语义**：图上的每条边、每个裁定、每处临界点都由纯 JS 规则引擎算出并可断言复核。**"画得像"与"算得对"是两条赛道**。

## 一、项目介绍

规则集（eligibility 判定、风控策略、政策准入、信贷审批、报销规则、游戏规则等）在现实中以 **JSON/YAML 配置**或**文档表格**形态存在，业务方真正想看的从来不是"规则文本"，而是三件事：**① 输入落在哪条路径上、最后裁定是什么；② 改一个字段，结果会不会翻盘、从哪条边分叉；③ 数值条件的临界点到底是多少**。这三件事靠"读规则文本"回答不了，靠"AI 画一张流程图"也回答不了——**图会画错、边界会画飘、反事实全靠猜**。

本工具把规则集**编译**成一张可交互的决策树：用户点击输入走通路径，看到确定性裁定；拖动/切换一个字段，引擎重算并**高亮两次路径集合的差**（`path(A) Δ path(A')`）；对每个数值条件**二分搜索**出精确临界值，并给出满足 `eval(v) ≠ eval(v+ε)` 的临界点证据。

**与"AI 画图"的三条本质区别**：**①求值而非描述**——输出节点是规则引擎逐条布尔求值的结果，同输入重复运行字节级一致；**②坐标由算法算而非模型猜**——决策树用 tidy-tree（Reingold–Tilford）算节点 (x,y)，决策边界图用确定性 N×N 网格扫描求值算边界折线，**模型永不产出坐标**；**③可证伪**——路径差、临界点、覆盖率全部是可写单元测试的断言，不是"看起来对"。

## 二、任务要求

> 首期范围限定为**规则集输入 schema + 确定性规则引擎 + 单文件 HTML 渲染 + 反事实与阈值二分 + 校验器与真值基准**五个模块；决策边界图（2D 网格扫描）、多规则集对比、SVG/PNG 导出留扩展。全部模块遵循确定性纪律：**模型永不产出坐标、永不产出裁定结果**——模型只做规则集的自然语言解读、节点文案润色、配色/主题、图例措辞、结论标题等**表达层**工作。

### 1）SKILL.md 主入口 + 规则集输入 schema（JSON/YAML）

- **输入**：一份 eligibility／风控／政策规则集（JSON 或 YAML），字段化的条件（数值阈值、布尔开关、枚举分类）与裁定输出；
- **输出**：SKILL.md 主入口 + 规则集 schema 定义（条件类型、裁定字段、规则优先级/互斥、默认裁定），schema 随包；
- **确定性纪律**：schema 校验是确定性的（同一规则集 → 同一校验结论）；schema 不合规的规则集**拒绝进入求值路径**并如实报错，不猜测补全。

### 2）确定性规则引擎（纯 JS / Python 标准库，无 LLM）

- **输入**：`rules.json` + `case.json`（一条具体输入案例）；
- **输出**：逐条布尔求值结果、走通的完整路径（节点序列 + 边序列）、最终裁定；
- **确定性纪律**：**纯 JS（约 200 行量级，无第三方库、无 LLM）**逐条求值；**同输入重复运行字节级一致**（可写断言：两次运行输出 JSON 的 sha256 相同）；引擎代码里**零规则字面量**（阈值只存在于规则集，一处定义多处引用）。

### 3）单文件 HTML 渲染（内联 SVG，tidy-tree 布局手写，零 CDN）

- **输入**：规则集 + 引擎求值结果（图结构 + 裁定）；
- **输出**：**单个 .html 文件**（内联 CSS/SVG/JS，零 CDN、零外部资源、无网络请求），含内嵌 `__DECISION_GRAPH__` JSON；
- **确定性纪律**：决策树节点 (x,y) 由 **Reingold–Tilford/tidy-tree 算法手写实现**算出，**坐标不来自模型**；同一规则集重复渲染产出**同一布局**（坐标可断言）；模型只可改节点文案/配色/主题，**不可改坐标、不可改裁定**。

### 4）反事实对比与阈值二分（可点击交互）

- **输入**：当前案例 + 一个被改动的字段（反事实假设）；
- **输出**：①重算后的路径与裁定；②**高亮分叉边集合**；③每个数值条件的**临界点**（二分搜索结果）；
- **确定性纪律**：**反事实差异可校验**——高亮分叉边集合必须**等于**两次路径集合的差 `path(A) Δ path(A')`（可断言）；**阈值可证伪**——临界值 `v*` 必须满足 `eval(v*) ≠ eval(v*+ε)`（可写单元测试）；交互只是触发器，求值仍走同一引擎，**交互层零判定逻辑**。

### 5）校验器（schema + 断言）与真值基准（合成规则集 + 植入真值）

- **输入**：规则集 + 生成的 HTML + 引擎求值记录；
- **输出**：校验报告 + 合成基准评测结论；
- **确定性纪律**：
  - **schema 校验**：内嵌 `__DECISION_GRAPH__` JSON 按固定 schema 断言——**节点数 = 规则数、每边对应一条件、无孤儿节点、每路径终止于叶子裁定**；
  - **覆盖率自检**：枚举规则组合，报告**不可达节点／矛盾规则／恒真条件**（纯算法）；
  - **真值基准**：程序化生成**合成规则集 + 植入真值**（假业务场景白名单，如假"入组资格／报销规则"），真值 = 程序化标注的**已知路径 / 已知临界点 / 已知不可达节点**；一条命令复现评测，指标口径写进 README；
  - 校验器为 `pytest`（Python 路径）或 `validate.js`（JS 路径）实现，二者口径一致。

### 6）扩展项（不承诺首期交付）

- **决策边界图**：2D 网格扫描（确定性 N×N 求值）画出两个数值条件构成的裁定边界折线，留扩展；
- **多规则集对比**：同时编译多份规则集并对比裁定差异，留扩展；
- **SVG/PNG 导出**：从单文件 HTML 导出静态图，留扩展。

## 六、边界与非目标

- **不做规则集创作**：规则集由**用户提供**（本工具是编译器/可视化器，不是规则生成器）；模型只做解读与歧义澄清，不替用户发明规则。
- **不做"AI 画图"**：**坐标必须算法生成**（tidy-tree / 网格扫描），模型**永不产出坐标**；不承诺视觉美观超越 archify（83823★），**差异化在求值**而非美观。
- **隐私红线**：**纯本地处理**，规则集与案例**不上传**、不调用外部 API、零网络请求；单文件 HTML 无 CDN、无外部资源。
- **品牌隔离**：不复制姊妹项目代码；公开文档不提其余项目业务领域。
- **首期范围限定**：以**决策树 + 反事实 + 阈值二分**为主，**决策边界图列扩展**；多规则集对比、SVG/PNG 导出留扩展。
- **数值口径**：**不写会随实现漂移的硬数字**（引擎行数、节点数、测试数写"以末态回填"）；数值阈值**一处定义**（规则集）、多处引用；合成基准**指标口径与门槛来源写进 manifest/README**，不写死通过数。
