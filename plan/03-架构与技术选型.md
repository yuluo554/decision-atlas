## 一、技术选型决策（含否决项）

| # | 决策点 | 选择 | 否决的备选与理由 |
|---|---|---|---|
| 1 | 引擎语言 | **JS**（运行时底线 **Node ≥22**（2026-10-20 自 M0 初稿抬高，见 §六）与现代浏览器共通的 ES2020 子集；JSDoc 注释补类型） | ✗ Python 双路线：交互求值（点击重算）**必须在浏览器内运行**，双语言=双实现=口径漂移源；✗ TypeScript：需引入构建链，违背零依赖 |
| 2 | 运行形态 | 本地 CLI（编译/校验/基准）+ **file:// 直开的单文件 HTML**（交互） | ✗ 本地服务器/FastAPI 类面板：违背"无服务器、零 CDN"承诺；且 file:// 下 ES Module 受 CORS 限制，产物必须内联**非模块**脚本（打包器设计的直接约束，见 04 §9） |
| 3 | 依赖策略 | **零第三方依赖（含工具链）**：测试用 `node:test`，打包用自研极简 bundler（约定受测试约束） | ✗ npm 依赖/构建框架（vite/rollup）：零依赖本身是卖点与纪律；✗ zod/ajv 等 schema 库：自写校验器才能做到"拒绝+不猜测"的可控错误码 |
| 4 | 校验器形态 | `tools/validate.js`（Node，与引擎同语言） | ✗ pytest 双实现：题目允许二选一（"二者口径一致"），单实现彻底消灭口径分裂 |
| 5 | 布局算法 | **tidy-tree 系（Reingold–Tilford 思路）手写** | ✗ 力导向：不可复现（依赖迭代/种子）违背确定性纪律；✗ 第三方布局库：零依赖 |
| 6 | 输入解析 | JSON 为**规范格式**；YAML 文档化**子集**（M2 手写确定性解析器） | ✗ YAML 全语法：零依赖下手写风险高；✗ 仅 JSON：题面写明"JSON 或 YAML"，子集+显式报错是诚实折中（D-03） |
| 7 | 测试 runner | `node:test` 内置（`node --test`） | ✗ jest/vitest/mocha：外部依赖 |
| 8 | CI | GitHub Actions：ubuntu + windows × Node 22/24（**M6 首推后生效**；无远端期间按"本地等价校验"纪律留档） | ✗ 首推前不建远端：遵循发布里程碑统一建仓（00 已定） |

## 二、模块图与数据流

```
                 ruleset.json(/yaml 子集)      case.json(可选)
                        │                          │
                 src/schema.js  ── 校验 ──────────┤
                        │                          │
                 src/graph.js  ── 编译 ───────────┤        （列表模式→树：FR-15）
                        │                          │
   src/coverage.js ◄────┤                          ▼
   （覆盖率自检）        │                    src/engine.js ──► trace（路径/边/裁定）
                        ▼                          │               │
                 src/layout.js（坐标，纯函数）      │     ┌────────┴─────────┐
                        │                          │     ▼                  ▼
                        ▼                          │  src/counterfactual.js  src/bisect.js
                 src/render.js ◄─── 图+坐标+trace ─┘  （path(A)Δpath(A')）（v*/ε 证据）
                        │
                        ▼
                单文件 HTML（内联 SVG/CSS/JS + __DECISION_GRAPH__）
                        │
              tools/validate.js（schema 断言+覆盖率，M4）
              tools/bench.js + tools/gen_bench.js + data/benchmark（真值基准，M1/M4）
```

**数据流总结**：`ruleset(+case) → 校验 → 编译（graph 结构）→ [求值 trace / 布局坐标] → 渲染单文件 HTML`；旁路 = 覆盖率（消费 graph）、反事实（消费两条 trace）、二分（消费 engine）。

## 四、确定性纪律体系（五类门，逐条可证伪）

| # | 纪律 | 落地机制 | 证伪位置 |
|---|---|---|---|
| G1 | **求值确定性** | `canonical.js`（键排序/无空白/非有限数报错）+ sha256；引擎纯函数 | 引擎测试双跑；CLI `selftest`；M2 起基准 |
| G2 | **坐标可断言** | 布局为纯函数、坐标唯一产出点；渲染只消费坐标 | 布局双跑相等 + 结构不变量测试；渲染字节级一致测试 |
| G3 | **零规则字面量** | 引擎/渲染/前端源码不得含规则集阈值（门禁扫描，M2 建立；原则从骨架起） | 门禁测试 0 命中（扫描面含注释/文档字符串） |
| G4 | **无时钟无随机** | `src/`、`tools/`（生成器除外）禁 `Date.now`/`Math.random`；生成器用自研 splitmix64（M1）；产物无时间戳 | 源码扫描测试 + 产物无 ISO 时间戳模式测试 |
| G5 | **零外链零网络** | 产物无外部引用（白名单仅 `http://www.w3.org/...` 命名空间 URI）；源码无 `fetch`/`XMLHttpRequest`/动态 `import(` | 渲染产物扫描测试；断网可开（M3 起 headless 复验） |
| G6 | **字节纪律** | `.gitattributes`（eol=lf）+ CR 守门测试；文本产物 LF；JSON canonical 稳定 | `tests/hygiene.test.js`；渲染双跑 sha256 |

**"模型只做表达层"的落法**：仓库内不接任何 LLM/API；节点文案/配色由规则集字段与本地样式表决定——即"表达层素材入数据，不入模型"。SKILL.md（M5）说明：Agent 可替用户润色文案，但**不可改坐标、不可改裁定**（改文案=改 ruleset 中 label 字段并重编译，产物重算）。

## 五、隐私与交付形态

- **隐私红线**：纯本地处理；规则集与案例不上传、不调外部 API、零网络请求；单文件 HTML 无 CDN、无外部资源。用户私有规则集目录 `data/**/_private/` 等已入 .gitignore。
- **交付形态**：GitHub 公开仓库 `decision-atlas`（沿用系列惯例 `yuluo554/<kebab-name>`，M6 发布）；仓库根即 Agent Skill 包（`SKILL.md` + `src/` + `tools/` + `data/`）；Release 附示例单文件 HTML + 演示 GIF/截图（M6）。
- **品牌隔离**：公开文档不提及姊妹项目业务领域（计划期措辞即按方向级描述，见 00 决策记录）。

## 六、环境与兼容

- **Node**：≥22（本机 v24.15.0）；CI 矩阵 Node 22/24 × ubuntu/windows（两档均在 `engines` 范围内）。
- **浏览器目标**：现代 Chromium/Firefox/Safari；本机验证用 Edge headless（已探测可用：`C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`）。
- **平台**：Windows 本机开发 + CI 双平台；脚本一律相对路径 + `import.meta.url` 定位仓库根（不依赖 CWD）。
- **行尾**：本机 `core.autocrlf=true` → 以 `.gitattributes`（`* text=auto eol=lf`）强制 LF，配 CR 守门测试。
- **编码**：全部 UTF-8；Node 原生支持，无 Python 控制台编码问题（本项目无 Python 通道）。
