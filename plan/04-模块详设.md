# 04-模块详设

**状态**：**schema v1 冻结（M1，2026-10-15，勘误见 §1.8）**。**作用**：冻结模块级契约与不变量；M2–M4 据此实现。**口径变更纪律**：本文任何"动了会打挂测试"的条目同时登记为 HANDOFF 的 K 编号。

> **回填口径**：引擎规模写"核心求值内核约百行量级、`src/` 全量以末态回填"（口径式表述非承诺）；节点数/测试数/覆盖率"以末态回填"；所有数值阈值只在规则集内定义一处。

## §1 规则集 schema v1 规格（**已冻结 M1 2026-10-15**，勘误 §1.8）

### 1.1 顶层字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema_version` | ✅ | 字符串；v1 冻结为 `"1"` |
| `ruleset_id` | ✅ | 全局唯一 id（基准用 `SYN-*` 白名单场景前缀） |
| `title` / `description` | title ✅ | 展示文案 |
| `mode` | 可选 | `"tree"`（默认）\| `"list"`（FR-15，M2 实现） |
| `inputs` | ✅ | 输入字段声明（见 1.2） |
| `verdicts` | ✅ | 裁定叶子（见 1.3） |
| `root` / `nodes` | tree 模式 ✅ | 显式决策树（见 1.4） |
| `rules` | list 模式 ✅ | 有序规则（首命中生效；与 `nodes` 互斥，见 §3） |
| `default_verdict` | list 模式 ✅ | 无命中时的裁定；tree 模式可选（配合 `"$default"` 哨兵引用） |

### 1.2 `inputs[]`（输入字段）

`{key, type, label, unit?, values?, search_range?}`

- `type ∈ {number, boolean, enum, string}`；
- `key` 唯一，`^[A-Za-z_][A-Za-z0-9_]*$`；
- `values`（enum 必填）：非空数组，成员限**字符串**（v1 冻结勘误：v0 文本曾写"string 或 number"，实测案例校验对 enum 取值恒按 string 校验，number 成员将导致案例永远无法过校验 → v1 收紧为纯字符串，见 §1.8 勘误 F-2）；
- `search_range`（number 可选）：`[lo, hi]` 有限数且 `lo < hi`——仅用于阈值二分的搜索域（§6），缺失则跳过该场二分并**如实报告 skip**。

### 1.3 `verdicts[]`（裁定）

`{id, label, kind, detail?}`；`kind` 为自由字符串（推荐 `approve / reject / refer / info`）——引擎与校验器**不解释 kind 的语义**，只做展示分类。

### 1.4 条件（`condition` / `when`）

- 原子：`{field, op, value}`；
- 复合：`{all: [cond…]}` / `{any: [cond…]}`（递归，非空数组）；
- 算子按类型白名单：

| type | 允许算子 | value 约束 |
|---|---|---|
| number | `>=` `>` `<=` `<` `==` `!=` | 有限数 |
| boolean | `==` `!=` | true/false |
| enum | `==` `!=` `in` `not_in` | 单个成员 / 成员数组 |
| string | `==` `!=` `in` `not_in` | 字符串 / 字符串数组 |

**复合条件的分解指引**（SKILL.md 使用）：复合逻辑鼓励拆成链式节点（每个节点一条原子条件），使树形、覆盖率分析与临界点定位都更精细；`all/any` 保留给确实不宜拆分的场景。

### 1.5 tree 模式 `nodes[]`

`{id, label?, condition, branches: {yes: <ref>, no: <ref>}}`；`<ref>` = 节点 id \| 裁定 id \| `"$default"`。

### 1.6 校验规则（错误码表，M1 冻结）

| 错误码 | 触发条件 |
|---|---|
| `E_SCHEMA_VERSION` | 版本缺失/不支持 |
| `E_REQUIRED` / `E_TYPE` | 必填缺失 / 类型不符 |
| `E_ID_DUP` | inputs key / 节点 id / 裁定 id 重复；节点 id 与裁定 id 冲突 |
| `E_ROOT_MISSING` | tree 模式 root 缺失或指向不存在项 |
| `E_REF` | 分支引用悬空（既不是节点也不是裁定） |
| `E_CYCLE` | 树中存在环 |
| `E_UNREACHABLE` | 存在从 root 不可达的节点（结构孤儿） |
| `E_FIELD_UNKNOWN` | 条件引用了未声明的输入字段 |
| `E_OP` | 算子对该字段类型不允许 |
| `E_VALUE` | 条件值类型不符 / enum 成员不在 `values` 内 |
| `E_COMPOUND_EMPTY` | `all/any` 为空数组 |
| `E_SEARCH_RANGE` | 非 number 携带 / 区间非法 |
| `E_MODE` | `mode` 与 `nodes`/`rules` 组合不合法 |
| `E_DEFAULT_MISSING` | 使用 `"$default"`（或 list 模式）但缺 `default_verdict` |
| `E_CASE_MISSING` / `E_CASE_UNKNOWN` / `E_CASE_VALUE` | 案例缺字段 / 多字段 / 值类型不符 |

**行为契约**：校验失败 → **拒绝进入求值路径** + 逐条错误码报出（exit 1）；**绝不猜测补全**。

### 1.7 案例（case.json）

`{fieldKey: value, …}` 平铺对象；**必须覆盖全部 inputs**（缺一即 `E_CASE_MISSING`）；类型错/枚举越界报 `E_CASE_VALUE`；多余键报 `E_CASE_UNKNOWN`（防笔误静默）。

## §2 引擎语义（`src/engine.js`，M2 完成）

- `evaluateCondition(cond, values) → boolean`：纯函数；复合递归求值。
- `traceRuleset(ruleset, values) → Trace`：

```jsonc
{
  "ruleset_id": "SYN-XXX-001",
  "nodePath": ["n1", "n2", "n3"],                       // 走通的节点序列
  "edges": [ {"from":"n1","branch":"yes","to":"n2"}, … ],// 走通的边序列（branch ∈ yes|no；**含进入裁定的终端边**，勘误 F-5）
  "steps": [ {"node":"n1","result":true,"branch":"yes","next":"n2"}, … ],
  "verdict": {"id":"V.pass","label":"…","kind":"approve"}
}
```

- 遍历：`cur=root` → 求值当前节点条件 → 取 `branches[yes|no]` → 命中裁定则终止；步数 > 节点数即内部错误（结构上不可能，防御性断言）。
- **求值确定性**：同输入重复运行，`canonicalStringify(trace)` 的 sha256 相等（测试 + `selftest` 双跑断言）。
- **零规则字面量**：引擎源码不得出现规则集阈值/裁定串（扫描门禁 M2 建立，扫描面含注释）。
- list 模式（M2）：按序逐条求值、**首命中生效**；无命中 → `default_verdict`；trace 的 `nodePath` = 已求值规则序列（含命中条），未求值的规则不出现。
- **交互层零判定逻辑**：浏览器运行时只做"取值 → 调本引擎 → 映射展示"，不得内联任何条件判断/算术（M4 起以静态断言防漂移）。

## §3 编译层（`src/graph.js`）

- `buildGraph(ruleset) → Graph`：`{ruleset_id, root, nodes:[{id,label,condition,yes:{to,kind},no:{to,kind}}], verdicts:[…]}`；`kind ∈ {node, verdict}`。
- **不变量**（build 时断言；M4 校验器对产物复验）：
  1. 节点数 = 规则数（tree：= `nodes.length`；list：= `rules.length`）；
  2. 每条边可归因到源节点条件的一个极性（yes/no 各至多一条）；
  3. 无孤儿节点（全部从 root 可达）；
  4. 每路径终止于叶子裁定（无环、无悬空引用）。
- **list→tree 编译（M2，FR-15）**：`r1 → yes: verdict(r1), no: r2`；…；`rN → yes: verdict(rN), no: $default`；`$default` 解析为 `default_verdict` 叶子。编译等价性判据：对任意案例，编译前（列表语义）与编译后（树遍历）的裁定与"首命中规则"一致（对账测试）。

## §4 布局（`src/layout.js`）

- `layoutGraph(graph) → {positions: {id:{x,y,depth}}, width, height}`；**坐标唯一产出点**（模型/运行时均不可改）。
- **v0（M0）**：DFS（children 顺序固定 `[yes, no]`）给叶子按序号分配 `x = index * X_GAP`；内部节点 `x = (yes.x + no.x)/2`；`y = depth * Y_GAP`。常量集中在 `LAYOUT` 对象（X_GAP/Y_GAP/节点尺寸/内边距）。
- **M3 升级**：Buchheim/tidy 精化（缓解不平衡树的观感问题）；升级前后均须保持：双跑坐标完全相等 + 结构不变量（叶子 x 严格递增、父节点 x = 子节点中点（v0 断言）/ 父节点居中于子节点范围（M3 断言））。
- 渲染层只消费坐标，不做任何坐标运算（除线宽/圆角等样式偏移）。

## §5 反事实对比（`src/counterfactual.js`，M2）

- 边身份 = `from + branch`（目标由树结构唯一决定，无需参与身份）。
- `diffPaths(traceA, traceB) → {onlyA, onlyB, common, divergeIndex, divergeNode}`：`onlyA/onlyB` 为对称差两侧（`path(A) Δ path(A')`），`common` 为交集；`divergeIndex` = 首个 `(from,branch)` 不同的 step 下标（答"从哪条边分叉"）。
- **断言契约**：HTML 高亮的分叉边集合 **==** `path(A) Δ path(A')`（集合等式，双向包含都断言）；合成真值库植入已知反事实对做端到端对账（M4）。
- 浏览器交互（M3）：改一个字段 → 引擎重算 A' → diff → 高亮；**交互层零判定逻辑**（恒有）。

## §6 阈值二分（`src/bisect.js`，M2）

- 目标函数：数值字段 f、基准案例 A：`g_f(v) = trace(A[f:=v]).verdict.id`。
- 前置：f 出现在 ≥1 条件中、且声明 `search_range=[lo,hi]`；否则**跳过并报告 skip + 原因**（不猜范围）。
- 流程：
  1. **粗扫**：N0 = 256 个等距采样点（含端点），找相邻异值对（转折候选）；
  2. **细二分**：对每个转折对 (a,b) 二分至 `b-a ≤ ε`（ε = 1e-6，**精度约定**非规则数值）；
  3. 报告全部转折（上限 16，超出标 `too_many`）；0 转折 → `no_boundary`（合法结论）。
- 证据自足（可证伪核心）：每条边界报告 `{field, v_star: a*, v_plus_eps: b*, verdict_at, verdict_plus_eps}`——任意第三方用同一引擎复核 `g(a*) ≠ g(b*)` 且 `b*-a* ≤ ε`。
- 不做单调性假设：多转折逐一如实报告；`eval` 一律指**全裁定函数**（其他字段固定在 A 的值）。

## §7 覆盖率自检（`src/coverage.js`，M4）

- 沿树做抽象解释：对每个字段维护路径约束——
  - number：区间（含端点开闭标记）；boolean/enum/string：可能值集合；
  - 逐边求交；三值逻辑 `{可行, 不可行, 未知}`：**复合条件的否定分支不细化 → 标"未知"**（宁可少报不可假报）。
- 报告三类：`unreachable_branch`（分支约束与前缀矛盾，如 `<100` 之后又要求 `>=120`）、`contradiction`（同一路径上规则互斥，归并为不可达原因）、`tautology`（极性被前缀蕴含的恒真/恒假条件）。
- 输出 JSON + 文本双轨；M4 与真值库植入的已知集合做 precision/recall 对账。
- **诚实口径**：证明不了的一律 `unknown` 显式列出，不折算成"没问题"。

## §8 校验器（`tools/validate.js`，M4）

对"规则集 + 产物 HTML"校验：

1. 规则集/案例：复用 `src/schema.js`；
2. 产物：从 `atlas-graph` 标记抽取 `__DECISION_GRAPH__` JSON，断言 §3 不变量 1–4 + 坐标有限 + 无外链（G5）；
3. `--check` 模式：按规则集重渲染并与给出产物**逐字节比对**（sha256）——防"产物与规则集脱钩"。

退出码：`0` 全过 / `1` 断言失败 / `2` 用法或输入不可用。

## §9 渲染与运行时（`src/render.js`，骨架 v0 → M3 完成）

- **产物结构（标记契约，测试依赖）**：
  - `<script type="application/json" id="atlas-graph">` 内嵌 `__DECISION_GRAPH__`（全部 `<` 转义为 `\u003c`，防脚本闭合）；
  - 单个**非模块** `<script>`（file:// 兼容）：`const __DECISION_GRAPH__ = JSON.parse(…)` + 引擎 bundle + 交互 UI；
  - **预渲染 SVG**（build 时消费坐标；运行时只切 class，不重画）；
  - 内联 CSS（系统字体栈、无外链字体）；页脚含版本与规则集 sha256 摘要。
- **运行时职能**：v0 = 字段面板（number/boolean/enum/string）→ 引擎重算 → 路径高亮 + 裁定横幅；M3 增 = 反事实 Δ 高亮（vs 基准案例）、阈值面板（消费 §6 结果）、细节打磨。
- **字节稳定**：产物无时间戳；同输入双渲染**逐字节一致**（测试断言）；无外链（白名单：`http://www.w3.org/...` 命名空间 URI）。
- **打包器**（`src/bundle.js`）：零依赖硬约束下的极简确定性方案——约定（受测试强制）：待入包模块只含顶层函数声明/const + 顶层单行 `import`/`export` 语句；打包 = 按声明顺序拼接 → 删除 import 行 → 去 `export ` 前缀 → 断言无残留（`import`/`export`/`require(`/动态 `import(`）。bundle 在 Node `vm` 中可执行（测试）。

## §10 真值基准（`tools/gen_bench.js` + `tools/bench.js` + `data/benchmark/`，M1/M4）

- **真值库格式**（只存输入与期望；**禁 `observed` 类字段**——冻结件里出现"观测"即红）：

```jsonc
{ "case_id": "…", "ruleset": "bench-xxx.rules.json",
  "input": { … }, "expect": { "verdict": "V.x", "nodePath": ["…"], "edges": ["n1:yes", "…"] } }
```

- **指标**（门槛随 `manifest.json` 下发，数据非代码）：路径准确率 / 裁定准确率 / 临界点命中率（与植入边界 ε 邻域对账）/ 不可达检出（precision/recall，与植入集合对账）/ 反事实 Δ 对账。
- **探活**（每套件注入缺陷 → 基准必须报未达标）：篡改期望、坏引用规则集、边界挪动 ε 外、不可达注入（期望不可达但实际可达）。
- 命令：`node tools/bench.js`（退出码 0/1/2 语义锁进测试）；`--only <suite>` 白名单，未知名 → exit 2；覆盖声明**总数/采样数双登记**（抽样非穷举）。
