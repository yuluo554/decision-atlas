## 二、生成器设计（`tools/gen_bench.js`，M1）

### 2.1 确定性纪律（生成器专属，优先级最高）

- **禁 `Math.random`、禁 `Date.now`/时钟、禁对象迭代序依赖**：自研 **splitmix64**（BigInt 或 32 位双字实现）作唯一随机源，固定 seed；
- 落盘产物**无时间戳**（JSON 键序固定、无 `generated_at` 类字段）；
- 两次独立运行**逐字节一致**（LF 行尾）；`--check` 模式：重生成并与已冻结文件逐文件比对 sha256，不一致即 exit 1 并列出差异文件（**位级守门**）。

### 2.2 场景与模板

- 白名单场景定稿（M1）：`SYN-ENROLL`（假入组资格）/ `SYN-REIMB`（假报销）/ `SYN-CREDIT`（假信贷）/ `SYN-GAME`（假游戏）；每个场景以参数化模板生成多张树（覆盖数值/布尔/枚举字段、复合条件、链式拆分）；
- **植入真值构造法**（真值 = 生成时已知，非事后标注）：
  1. **已知路径/裁定**：按模板构造规则树时同步产出案例的期望路径（构造即真值）；
  2. **已知临界点**：阈值型节点（如 `f >= T`）在生成时记录 `(field, T 邻域)` 为已知边界；案例围绕 T 生成 `T-δ` / `T+δ` 对（δ 跨 ε 两侧多档）；
  3. **已知不可达/矛盾/恒真**：按"约束影子"技法植入——先沿某路径施加约束（如 `f < 100`），再在该路径深处放一个与之矛盾的条件（如 `f >= 120`）→ 该分支不可达为已知；反向植入"被前缀蕴含"的条件（如已 `f >= 100` 再检 `f >= 50`）→ 恒真为已知；
  4. **已知反事实对**：成对生成案例（仅一个字段不同），其 Δ 边集合由构造唯一确定并记录为期望。

### 2.3 规模与覆盖（数值以末态回填）

- 规则包总数 / 每包节点数档位（小/中/大）在 M1 定稿并登记于 manifest；
- **抽样非穷举声明**：真值库对规则组合为抽样覆盖（逐形态登记"规则包总数 / 采样数 / 采样清单"），任何"覆盖率"表述必须带分母。

## 三、真值库格式纪律

- **只存输入与期望**（`input` / `expect`）；观测（observed）由基准在**运行时用真值输入真喂引擎**产生——冻结件中出现"观测"字段即红（自证空转防线）；
- 期望键名**自带结论**（如 `"verdict:V.pass"`、`"edge:n3:no"`），取值恒为 `true` 一类哑值——集合比对时"状态一变键名就变"，防止误分类静默通过；
- 对账语义**单一实现源**（M4：`tools/bench.js` 与测试共用同一比较函数）；
- **不许改真值凑引擎**：区分①检查器谓词不自洽 → 只改谓词；②真值口径本身错 → 引擎与真值同源修正（同步重生成 + `--check` 复验），判据与处置写进决策记录。

## 四、冻结与位级守门

| 环节 | 守门 |
|---|---|
| 生成产物（规则集/案例/真值/manifest） | 生成器 `--check` 逐字节一致（M1 起）；**禁手改**，改需求=改生成器+整组重生成 |
| 行尾 | `.gitattributes`（eol=lf）+ CR 守门测试 |
| 采样清单 | manifest 登记（总数/采样数/清单三件） |
| 再现 | 一条命令：`node tools/gen_bench.js --check` |

## 五、门槛与指标（M4 定稿，M1 先立骨架）

- 指标定义（写入 manifest + README）：路径准确率 / 裁定准确率 / **临界点命中率**（报告边界与植入边界 ε 邻域内一致）/ **不可达检出** precision & recall / 反事实 Δ 对账一致率；
- 门槛是**数据不是代码**（manifest 下发）；基准层只读，缺失即 exit 2；
- 每套件**探活**：注入缺陷必须报未达标（"基准全绿"必须有可证伪性背书）；
- 不写死通过数：README 写实测值 + 日期，数字"以末态回填"。
