| **官方标准/法规数值** | **不引用** | 本题**不引用**任何官方标准/法规的数值条文（与"政策计算器"类题不同）；阈值全部来自**用户规则集**或**合成规则集**，故**无"文号/数值/日期"编造风险面** |

**结论**：本题是**纯算法/纯工程题**，无"数据底座不可获取"风险；核心风险在**确定性内核的正确性**（求值一致性、路径差、阈值二分、覆盖率自检），全部可程序化验证。

## 三、合成数据纪律（假业务场景白名单 + 植入真值）

### 3.1 合成规则集用**假业务场景白名单**

> **禁止**：使用真实机构的真实规则集作为基准样例（隐私 + 真实性红线）。
> **允许**：以下**假业务场景**（虚构、与真实机构无关），统一登记：

| 白名单场景 ID | 假业务场景（虚构） | 说明 |
|---|---|---|
| `SYN-ENROLL` | 假"入组资格"规则 | 虚构临床试验/研究入组的条件判定（年龄/指标/既往史等**假字段**） |
| `SYN-REIMB` | 假"报销规则" | 虚构报销准入的额度/类别/凭证条件（**假额度**） |
| `SYN-CREDIT` | 假"信贷审批"规则 | 虚构风控策略的评分/收入/负债条件（**假分值**） |
| `SYN-GAME` | 假"游戏规则" | 虚构升级/掉落的等级/道具条件（**假数值**） |

> 白名单为**示例**，M1 数据先行时**定稿**并逐条登记；新增场景须先入白名单再生成。

### 3.2 植入真值（程序化标注，禁手填）

合成规则集的真值**不由人手填**，而是**程序化标注**：

| 真值类型 | 生成方式 | 可证伪方式 |
|---|---|---|
| **已知路径** | 对每条合成案例，引擎求值得到节点序列 + 边序列 | 与冻结真值库逐条比对 |
| **已知临界点** | 对每个数值条件二分搜索临界值 `v*` | `eval(v*) ≠ eval(v*+ε)` 断言 |
| **已知不可达节点** | 覆盖率自检枚举规则组合得出 | 与程序化标注的不可达集合比对 |
| **已知矛盾规则/恒真条件** | 覆盖率自检识别 | 与程序化标注集合比对 |

**纪律**：真值库**冻结入仓**（生成器 `--check` 门 + 字节级一致守门）；基准**一条命令复现**；**指标口径与门槛来源写进 README/manifest**，**不写死通过数**。

### 3.3 案例来源

- **合成案例**：程序化生成（覆盖各规则分支 + 边界值 + 反事实对），带植入真值；
- **用户案例**：用户自行输入，**不入仓**（隐私），只在本地求值；
- **零真实数据**：基准与演示**一律合成**，无任何真实业务数据入库。

## 四、数值口径纪律

- **阈值一处定义**：所有数值阈值只存在于**规则集**一处；引擎、渲染、校验、基准全部**引用规则集**，引擎代码**零规则字面量**（门禁断言）；
- **不写漂移硬数字**：引擎行数写"约 200 行量级"（量级描述非承诺）；节点数/测试数/用例数写"**以末态回填**"；不写死通过数；
- **数值口径同源**：规则集的注记/说明文本与 plan 算法描述**同源**，禁止在注记里手写第二份口径表述；
- **门槛来源**：合成基准的达标门槛是**数据不是代码**，写进 manifest/README。
